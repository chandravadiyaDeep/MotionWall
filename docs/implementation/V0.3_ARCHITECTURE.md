# V0.3 Wallpaper Library — Architecture

## Goal
Replace the V0.2 in-memory sample list with a bundled, typed, validated catalog and original local thumbnail artwork. The catalog is offline-first and requires no permission, account, backend, or network request.

## Data flow
`assets/wallpapers.json` -> `WallpaperRepository` -> validated `Wallpaper` models -> existing Compose Home / Explore / Favorites / Detail screens.

- Catalog schema version is explicit (`schemaVersion: 1`).
- Artwork keys resolve through a closed, type-safe drawable map; unknown assets fail visibly.
- The repository validates required metadata, minimum color count, non-empty catalog, and unique IDs.
- Categories are derived from catalog data, not maintained as a second hard-coded list.
- Search covers title, category, and tags; category filtering remains composable with search.
- Catalog loading failures render a retryable error state.
- All data and artwork are bundled in the APK; the app remains usable offline.

## Asset policy
All V0.3 artwork is authored as native Android XML drawable compositions in this repository. No external images, scraped content, or third-party artwork are included. The asset register records each asset and its CC0-1.0 dedication for project use.

## Boundaries
- No video playback (V0.4).
- No WallpaperService or system wallpaper apply flow (V0.5).
- No persistent favorites/downloads (V0.7).
- No internet permission, remote catalog, or analytics.

## Validation
Unit tests cover catalog parsing, required fields, unique IDs, missing artwork, filtering, and favorite transformations. CI builds the debug APK and runs JVM tests. Device visual checks remain a required manual acceptance step.
